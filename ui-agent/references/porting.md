# porting：把别人的 Playwright / ai* 脚本翻成 ui-agent 用例

你手上常有的不是「一句话目标」，而是**已经写好的一份 Playwright + midscene 风格脚本**。
这份文档讲怎么把它翻成能跑的 YAML，以及**哪些行必须扔掉、哪些行只能人工补**。

核心差别先摆清：那种脚本里写着 `page.getByText('...')`、`aiTap('...')` 的定位，
内核**一个字都不执行**——它不接收选择器、不跑页面 JS、不认坐标。
它只接收「操作 + 目标标签」，目标定位由元素快照 + 标签子串匹配完成。
所以翻译不是语法改写，是**把「怎么找」丢掉、只留「做什么 + 凭什么算成功」**。

## 三条规则

### 规则 1：动作与断言按出现顺序落成步骤，断言挂到它前面那一步

脚本是线性的：一串动作 + 若干 `expect`。用例是分步的：每一步有 goal、有 checks。

- 连续的动作合成一步，**不要把每个动作拆成一步**（12 步上限，拆碎必超）。
- `expect` 归属**它前面最近的**那一步——它断言的是那串动作的结果。
- 开头没有断言的引导动作（`page.goto`）单独成第 1 步。

判据：一步做完，页面应该发生一次可观察的变化；没有变化的动作挤在同一步里。

### 规则 2：没断言的步骤，用「下一步要用的元素」补一条 `element_exists`

内核硬规则是**每步必须有 checks**（空数组报 `checks_empty`）。老脚本常常只有动作没有断言，
这时不要编造业务断言，按顺序借：

1. **前瞻**：看后面最近一个带目标描述的动作，取它的目标核心词，写 `element_exists: <词>`。
   这证明「这一步做完，下一步要的东西已经在页上了」。
2. **兜底**：后面也没有，就用本步自己的控件。
3. **都没有**：如实标注这一步没有断言来源，交给人补。

别把这三种混为一谈——**前瞻与兜底只证明控件还在，不证明业务对**。

### 规则 3：最后一步必须落到「结果类」断言

`element_exists` 不算验收（见 [cases.md](cases.md) 的五条硬规则）。最后一步只借到
`element_exists` 时，用例能跑但不算验完：报告里要写明「只证明控件还在，结果对不对没验证」，
然后人工补一条 `text_contains` / `element_value` / `element_count`。

## 逐行对照表

| 脚本里的写法 | 翻成 | 备注 |
|---|---|---|
| `page.goto('${{host}}/path')` | 第 1 步 goal「打开入口页面」 | **入口 URL 不进 YAML**，运行时用 `--url` 给。环境换了不用改用例 |
| `await page.waitForTimeout(3000)` | 删掉 | 内核每个动作后自己落定等待（settle）。写进用例只会白等 3 秒 |
| `aiInput('2515...', '发票号码输入框')` | goal「在「发票号码」填入用例给定的值」+ `vars` 里一个键 | 值进 `vars` 不进 goal；键名去尾词（见下） |
| `aiTap('查验按钮')` / `aiClick('查验按钮')` | goal「点击「查验」」 | 去尾词 |
| `aiHover('...')` | goal「悬停到「...」」 | |
| `aiKeyboardPress('Enter')` | goal「按「Enter」键」 | |
| `await expect(page.getByText('发票状态：正常')).toBeVisible()` | `text_contains: 发票状态：正常` | 冒号那条有坑，见下 |
| `expect(...).not.toBeVisible()` | `element_absent: <词>` | |
| `aiAssert('自然语言断言')` | **人工补** | 自然语言断言无法静态转成确定性断言 |
| `aiScroll('...')` / `aiSelect` / `aiUpload` / `aiDoubleClick` / `aiDragAndDrop` | **人工补**成目标描述 | 内核有对应操作，但脚本里那行的语义要人来判断 |
| `aiQuery` / `aiNumber` / `aiBoolean` / `aiString` / `aiLocate` / `aiWaitFor` | 删掉 | 取值类调用与用例无关；等待由 settle 负责 |
| `page.click('body')` / `page.fill(...)` / `page.locator(...)` / `page.getByText(...)` | **人工改写成目标描述** | 内核不收选择器。`page.click('body')` 这种「点空白处失焦」要显式写成点某个真实控件 |

## 目标描述 → 控件标签：去尾词

脚本作者写的是「人话」，快照里是「控件标签」。两者差在尾缀：

```
「发票号码输入框」→ 发票号码
「查验按钮」    → 查验
「搜索框」      → 搜索
```

按长度倒序剥这些尾缀（长的先剥，否则「输入框」会先被「框」吃掉）：

```
输入框 输入栏 文本框 搜索框 下拉框 下拉菜单 选择框 选择器 复选框 单选框 单选按钮
按钮 按键 链接 超链接 标签页 页签 选项卡 卡片 弹窗 对话框 区域 图标 控件 字段 输入区 框
```

剥完还超过 16 个字、或含 `${{` 的，**不要硬塞进断言**——那多半是一整句描述，
塞进去永远匹配不到，交给人看。

## 值进 `vars`，不进 goal

内核不把值交给模型：`TYPE_TEXT` 的实际文本由 `vars` 的键去匹配控件标签决定
（见 [security.md](security.md)）。所以翻译时每个输入值都要落成一个 `vars` 键：

- 键 = 目标描述的核心词（同样去尾词）。「发票号码输入框」的值 → 键 `发票号码`。
- 键名是控件标签的**子串**才算命中，这是内核算的，不是你看的。
- 值像凭据（键里有 `密码` / `口令` / `password` / `token` / `secret` / `凭据`）时，
  写成 `${{secret.键}}` 引用，**字面量不写进用例**；否则 `case compile` 会报 `literal_secret`。

### 标签会变的那种控件，键要挑「两边都有」的词

实测踩过：某表单的金额输入框**空着叫「金额合计」，填了值就叫「价税合计」**。
这时用 `--var 金额合计=...` 第一次能填进去，重跑就报「没有匹配 --var 的字段值」——
因为重跑时那格的标签已经是「价税合计」了。

修法不是改用例，是**换键**：用 `合计`（同时是两者的子串）。
通用于所有「填值后标签翻转」的控件（金额、日期、下拉选中态）。

### 日历别点开，直接打字

`aiInput('2025-05-07', '选择日期')` 翻过来时，目标照写「开票日期」，但**执行路径要挑打字**：
很多组件库的日历弹层里，日号是 `DIV` / `SPAN` 或 `em`，既不满足「弹层里的 `li`」也带不上
`tabindex`，**永远不会出现在元素表**（快照能收自绘下拉，见 [m3.md](m3.md) 第 3 节，
但日历日格不在那两条规则里）。一旦模型点了日期框把日历打开，它就找不到任何日期格可选，
只能在低置信度里打转（实测 Jev 连续 3 次 0.4 左右 → `low_confidence` 停机）。

直接对输入框 `TYPE_TEXT` 打字是通的（`开票日期` 的 `value` 实测变 `2025-05-07`）。
所以：**提示词里已写明「日期用 TYPE_TEXT，别开日历」**；你自己写 goal 时也别写
「点开日期选择器，选 5 月 7 日」这种描述——那等于指挥模型去踩坑。

确实只能点日历的页面（输入框只读），就靠 `--supervisor agent` 的 HINT 兜：
Jev 低置信度时把「别点日历、直接打字」交给它，或让它 `RECOVER` 到具体格。

### 让日期框失焦：用 Tab，不要按 Enter

日期框填完值后，它旁边的按钮常常还是 `disabled`（组件要等 `blur` 才回填校验）。
失焦手段有三种，行为**不一样**：

| 做法 | 结果 |
|---|---|
| 按 `Tab` | 安全。日期保持原值，按钮转可用 |
| 点别的真实控件（如「备注」） | 安全，同上 |
| 按 `Enter` | **危险**：很多日期组件把 `Enter` 当成「确认当前高亮日」，日期会被静默改成当天或面板默认值，而按钮**照样转可用**——从结果上完全看不出错，除非断言里有 `element_value: 开票日期\|2025-05-07` 这种值校验 |

所以：
- 用户脚本里的 `aiKeyboardPress('Enter')` / `page.keyboard.press('Enter')` 用来「提交」是另一回事；
  如果它的意图是**失焦**，翻成 `PRESS_KEY: Tab` 或「点某个真实控件」，**不要**照抄成 Enter。
- 用例里凡是填了日期，都补一条 `element_value: <日期控件标签>|<期望值>`，把这个坑钉死在断言里。
- 写 goal 时明说「按 Tab 让日期框失焦」，别写「按回车确认」。

### 横向溢出列里的按钮，内核看不到

宽表格（`scrollWidth` 远大于 `clientWidth`）整体横向滚动时，最右边的列在**视口之外**。
快照只收视口内的元素，所以那一列里的图标/按钮（典型是行尾「更多」）**根本不会出现在元素表里**，
也就 HOVER、CLICK 不到——不是点不中，是根本看不见。

实测：`myNoteAdd` 的列表宽 3034px、可视 1645px，行尾「更多」图标 `x≈3209 > 视口 1920`。
`scrollIntoView` 之后坐标变成 `x≈1842`（看起来可见了），但**快照里依然没有它**：
内核的快照是在滚动后重新取的，而那个图标所在的容器是滚动容器内的溢出区，
它的 `getBoundingClientRect()` 落在视口外，被快照的可见性过滤掉了。

遇到这种列，有三条路：
1. 该列有替代入口时走替代入口（例如「详情」按钮在视口内，能用它到达同一处）；
2. 把目标改成**结果类断言**（`text_contains`），别在用例里硬做这一步点击；
3. 真要这段交互，就用坐标级脚本或让宿主 `--supervisor agent` 给 HINT 说明「先横向滚到底」。

写用例时**先验证目标按钮在不在元素表里**：`case compile` 之后跑一次 `ui-agent snapshot`，
在 `elements` 里搜它的标签；搜不到就说明当前内核点不到它，别指望 `auto` 能兜。

## 冒号断言的坑

`text_contains: 发票状态：正常` 经常匹配不到，因为页面把标签与值放在**两个文本节点**里，
内核按文本节点换行拼接，整串中间会多一个换行。

失败时改成冒号后那段（`text_contains: 正常`）。但注意**别把断言削到没意义**——
只留「正常」两个字，页面上任何一处出现都算过。两步走：

1. 先写长的，跑一次看 `detail` 里实际拼出来的文本；
2. 按实际文本改断言，或改问「有没有更稳的证据」（`element_value`、`element_count`）。

## 翻完之后一定要做

```bash
uv run ui-agent case compile --in <场景>/<用例>.yaml --out <场景>/others/<用例>.plan.json
```

必须 `ok=true`、`errors=[]`。**`warnings` 也要逐条看**：

- `checks_empty` / `weak_final_check` → 规则 2/3 没做到位；
- `literal_secret` → 值没换成引用；
- `too_many_steps` / `too_many_checks` → 步骤拆碎了或断言堆多了。

编译过不等于跑得过：接着按 [running.md](running.md) 录制一次，跑挂了按
[debugging.md](debugging.md) 定位。

## 一个完整例子

脚本（节选）：

```js
test('发票查验票种：84 数电二手车', async ({ page, aiTap, aiInput }) => {
  await page.goto('${{host}}/bw-main-ui/incomeAlone-ui/income/invoiceCheck');
  await page.waitForTimeout(3000);
  await aiInput('25152000000023214079', '发票号码输入框');
  await aiInput('105000.00', '价税合计输入框');
  await aiInput('2025-05-07', '选择日期');
  await page.click('body');
  await aiTap('查验按钮');
  await page.waitForTimeout(3000);
  await expect(page.getByText('发票类型：数电票（二手车销售统一发票）')).toBeVisible();
  await expect(page.getByText('发票状态：正常')).toBeVisible();
});
```

翻出来（这是**真实跑通、零 token 回放过**的版本）：

```yaml
id: invoice-check-84
title: 进项·发票查验 84 数电二手车
notes: |
  入口地址运行时用 --url 给。
  自带登录（--var 账号=... --var 密码=...），干净 profile 也能跑。
  金额那格填值后标签从「金额合计」变成「价税合计」，键用「合计」两边都能命中。
steps:
  - goal: 打开入口。若出现登录页，就用给定账号密码登录
    checks:
      - text_contains: 云控制台     # 登录页没有、登录后才有 → 能区分「登进去了」
  - goal: 回到发票查验页
    url: /bw-main-ui/incomeAlone-ui/income/invoiceCheck   # 站内路径，按 --url 的 origin 补全
    checks:
      - element_exists: 发票号码    # 前瞻：下一步要填的控件已经在页上
      - element_exists: 开票日期
  - goal: 在「发票号码」「金额合计」「开票日期」里填入用例给定的值
    checks:
      - element_value: 发票号码|25152000000023214079
      - element_value: 开票日期|2025-05-07
  - goal: 点一下「备注」让日期框失焦，再点「查验」，等查验结果弹出
    checks:
      - text_contains: 数电票（二手车销售统一发票）   # 冒号前那段容易拼不上，去掉
      - text_contains: 正常
```

翻译时改了五处，都是有依据的：

1. **删了 `page.waitForTimeout` 与 `page.click('body')`**——前者由 settle 负责；
   后者是「点空白处失焦」，内核不收坐标式点击，改成点「备注」（真实控件）。
2. **`价税合计输入框` 的键用 `合计`**，理由见上面「标签会变」。
3. **断言去掉了冒号前缀**，理由见「冒号断言的坑」。
4. **补了第 1 步登录**。原脚本默认「已经登录」，但靠残留 cookie 才过的用例在别人机器上
   一定跑不过，而且跟铁律 13「做完清登录态」直接矛盾。登录步的断言要挑登录页没有、
   登录后才有 的文本（这里是「云控制台」），否则 `text_contains` 在登录页上也成立。
5. **补了第 2 步站内导航**。这个站点登录成功后停在云控制台、不回跳原始入口；
   而顶部导航菜单项与左侧菜单项都不满足快照的收录规则（既非可聚焦控件，也不是弹层里的
   `li`），**点不到**。只能显式导航：
   `url: /站内路径` 以内核 `resolve_step_url()` 按 `--url` 的 origin 补全，
   换环境只改 `--url`，用例一个字不用动。

最后一步留的是 `text_contains`，属于结果类断言，满足规则 3。

## 交接给用户时说什么

翻完不要只说「好了」。给三件事：

1. 哪几条是**机器翻的**、哪几条**人工补的**（尤其 `aiAssert` / `aiScroll` 那类）；
2. 哪些断言**只证明控件还在**、哪些才是真验收；
3. 跑一次需要什么：`--url`、几个 `--var` 键（**包括登录用的 `账号`/`密码`**）、
   是否自带登录（应该自带）、有没有需要显式导航的步骤。
