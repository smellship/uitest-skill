# m3：iframe、shadow DOM、遮挡、新标签、原生对话框

这些不是「高级特性」，是默认就该工作的能力。内核每一条都覆盖了，**但都有确定的边界**。
写用例前先 `snapshot` 看一眼元素表，比猜快得多：

```bash
uv run ui-agent snapshot --url <入口> --out snap.json --json
```

## 1. iframe：能穿透，但索引绑定在「当次快照」

- 快照**遍历页面里的全部 frame**，把所有 frame 的可交互元素放进同一张元素表，`index` 全局唯一。
- 带 `frame` 字段的元素来自子帧，值是该帧的 URL：

```json
{"index": 7, "role": "button", "label": "子页按钮", "frame": "http://127.0.0.1:8/m3_child.html"}
```

- 动作执行时，内核按「索引 → 所属 frame」的映射回到**元素自己的那个文档**里求值。
  上传的拖拽派发同理（`DROP_FILE_JS` 在目标帧里执行，不在主帧）。
- **索引只在当次快照里有效**。`snapshot` 一次、过几秒再动作，索引可能已经指向别的元素（`StaleTarget`）。
  这不是 bug，是「元素只能用当次快照 index 引用」那条铁律的直接后果。

### 跨域 iframe

Playwright 能进跨域 iframe，但**快照只能读到同源的**（页内 JS 受同源策略限制）。
不同源时那个 frame 不会出现在元素表里 → 你在用例里也点不到它。遇到就换入口（直接开子页 URL）。

### 用例里怎么写

不需要写任何 iframe 语法。goal 里说清「子页里的那个按钮」即可，元素表里它跟别的元素一样有 index：

```yaml
- goal: 在子页里点击「子页按钮」
  checks:
    - text_contains: 子页按钮已点击
```

## 2. shadow DOM：只覆盖 open

- 快照会**穿透各级 open shadow root**（`document` → 每个 `e.shadowRoot` 递归），影子里的按钮、输入框都在元素表里。
- 带 `shadow: true` 的元素来自影子树。**它在用例里跟普通元素没区别**，不用写 `>>>` 或 `::shadow`。
- 命中测试（判断「这个点能不能点到」）也逐层下钻：`document` → 宿主 → `shadowRoot.elementFromPoint`。
- **closed shadow root 拿不到**。页面 JS 进不去，内核也不能。遇到只能放弃，**不许猜 selector**——
  靠猜点中的往往是外层的宿主元素，表现为「点了没反应」，排查成本远高于承认做不到。

```yaml
- goal: 点击影子区里的「影子按钮」
  checks:
    - text_contains: 标记：影子按钮已点击
```

## 3. 遮挡：能看见但点不到，会被判出来

元素在视口里、但被别的元素盖住时，快照里带 `occluded_by`（遮挡者标签）：

```json
{"index": 6, "role": "button", "label": "被盖住的影子按钮", "occluded_by": "遮罩层"}
```

点击降级阶梯 L0–L3 正常尝试；**真遮挡（命中测试失败）时 L4 `CLICK_FORCE` 直接跳过**，
L5 合成事件仍会试，但会在 trace 与报告里标 ⚠，并进 `defect_candidates`。

这意味着：

- 你**不该**用 `CLICK_FORCE` 绕过遮挡来「把用例跑绿」。它是缺陷路径，写进报告是给人看的信号。
- 看到 `defect_candidates` 里有「点击被遮挡」，先对 `screenshots/failure.png` 确认，再决定是产品缺陷还是用例该等遮罩消失。
- 等遮罩消失靠断言轮询，不靠 `WAIT`：`text_contains` 配 `timeout_ms` 更可靠。

## 4. 新标签页：自动跟过去，但不自动关

- 内核在 `context.on("page")` 上登记所有新页，**不立刻切换**——切换发生在动作后的 `settle()` 里。
  这样「点击 → 新页打开 → 快照」是一条顺的动作，不用你写「等待新标签」。
- 当前页被关掉（`window.close()` 或用户点掉标签）时，内核切回剩下的最后一个页。
- **任何标签都不会自动关闭**。跑完一个用例，浏览器里可能留着几个标签——这是有意的，方便你看现场。
- 新标签、标签关闭都写成 `action="PAGE"` 的行为与 trace 的 `page_facts`：

```json
{"fact": "tab", "note": "跟随新标签页：http://127.0.0.1:8/m3_child.html"}
```

`PAGE` **不是动作**：不计入动作预算，不参与「重复三次没进展」的判定，也不写进 `actions.json` 的动作序列。

### 用例里怎么写

```yaml
- goal: 点击「在新标签打开子页」，跟过去确认子页打开了
  checks:
    - text_contains: 标记：无          # 主帧的标记没变，说明真的切走了
    - element_exists: 子页按钮
```

要点：验收断言要针对**新标签**的内容（`子页按钮` 只在子页里有）。
如果断言针对旧页的残留内容，回放时会对不上——因为回放里切换时机由录像决定。

## 5. 原生对话框：必须显式挂，否则假成功

`alert` / `confirm` / `prompt` / `beforeunload` 是浏览器级对话框，**不是 DOM 元素**，快照里看不到。
不挂监听时 Playwright 会自动 dismiss——于是「点了确认」变成「静默取消」，
页面看起来没变化，你却在用例里写了通过。所以内核**一律显式挂**并按策略应答。

```bash
uv run ui-agent run ... --dialog-policy dismiss   # 默认：一律取消
uv run ui-agent run ... --dialog-policy accept    # 一律确认（prompt 回填页面给的默认值）
```

| 对话框 | `dismiss` | `accept` |
|---|---|---|
| `alert` | 关掉 | 关掉（`alert` 没有返回值，两种策略等价）|
| `confirm` | 页面收到 `false` | 页面收到 `true` |
| `prompt` | 页面收到 `null` | 页面收到**页面自己给的默认值**（不是你编的）|
| `beforeunload` | 留在页面 | 允许离开 |

每一次应答都写进 trace 的 `page_facts` 与 `RecentAction`：

```json
{"fact": "dialog", "kind": "alert", "message": "这是一条提示", "handled": "dismiss"}
```
```json
{"action": "PAGE", "kind": "dialog", "text": "原生 alert 对话框：「这是一条提示」→ 已关闭"}
```

`handled` 三值：`accept`（已点确定）/ `dismiss`（已关闭）/ `failed`（应答失败）。

### `confirm` / `prompt` / `beforeunload` 一律记缺陷候选

内核把这三种当成「由配置代替用户应答」的事实，写进 `defect_candidates`：

```
决策#3 原生 confirm 对话框：「确定要继续吗？」→ 已关闭
```

**这是提醒，不是判定。** 用例通过时它也会出现在 `result.json` 的 `defect_candidates` 里。
要把它当缺陷上报，得先回答：这个确认框本该由用户决定吗？如果是，那就是产品的可用性问题（阻断式交互）。

### 用例里怎么写

对话框没有 DOM，只能验**它造成的后果**：

```yaml
- goal: 点击「弹个确认」，按 accept 策略应答
  checks:
    - text_contains: 确认返回了 true      # 页面自己把 confirm 的返回值写进了 DOM
```

如果页面不把返回值写进 DOM（大多数真实站点如此），就只能验「后续流程推进了」：

```yaml
- goal: 点击「删除」，在确认框上点确定，等列表少一行
  checks:
    - element_count: 数据行|2
```

**不要在 goal 里写「点确定」而以为那是对话框的确定**——goal 里的「确定」指页面上的按钮。
对话框由 `--dialog-policy` 统一决定，case 级别不能逐次指定。需要「这次点确定、下次点取消」的用例，
拆成两次运行，用不同 `--dialog-policy`。

## 6. 一次验完这五条的本地夹具

`kernel/examples/m3_fixture.html`（+ `m3_child.html`）就是为这些能力造的，不联网：

```bash
uv run ui-agent snapshot --url "file:///D:/path/to/ui-agent/kernel/examples/m3_fixture.html" --json
```

元素表里应该能看到：`子页按钮`（带 `frame`）、`影子按钮`（带 `shadow`）、
`被盖住的影子按钮`（带 `occluded_by: "遮罩层"`）、`在新标签打开子页`、三个对话框按钮。

实测 `element_count: 8`。看不到 8 个就是环境问题，先回去跑 [setup.md](setup.md)。

## 边界速查

| 能力 | 支持 | 边界 |
|---|---|---|
| iframe | ✅ 所有 frame 元素进同一张表 | 跨域 frame 读不到；索引只在当次快照有效 |
| shadow DOM | ✅ open，逐层穿透 | **closed 拿不到**，遇到只能放弃 |
| 遮挡 | ✅ 判得出、写进 `occluded_by` | L4 force 会被跳过；别拿它刷绿 |
| 新标签 | ✅ 自动切、自动记 `PAGE` | 不自动关；切换只在动作后 `settle()` |
| 原生对话框 | ✅ 显式挂 + 策略应答 | 快照里看不到；`confirm`/`prompt`/`beforeunload` 记缺陷候选 |
| 上传 | ✅ `input` / `drop` 两种 | 见 [cases.md](cases.md) 的 UPLOAD 节 |
| 网络请求/响应 | ❌ **不支持** | 全库无 `page.on("response")`；接口 500 而页面没变化，内核看不见 |
